# GitHub portfolio maintenance guide

## Before publishing a project
- [ ] Confirm the repository is public and the README describes the current code.
- [ ] Add real screenshots or a short demo.
- [ ] Document setup steps and required environment variables without committing secrets.
- [ ] Add build and test instructions that have been verified.
- [ ] Link the live store listing only if it is public and active.
- [ ] Use measured metrics only; include the measurement period and source.
- [ ] Add a license if you intend others to reuse the code.

## Keep the profile credible
- Prefer a small number of well-documented projects over many empty repositories.
- Pin 3–6 repositories that best demonstrate engineering ability.
- Keep project descriptions specific: problem, implementation, trade-offs and outcome.
- Never publish API keys, signing keys, passwords, private user data or confidential employer code.
- Review badges and external links periodically.

## Suggested pinned repositories
1. DevPulse AI — if its source repository is public and ready for review.
2. A flagship native Android app with a clear README and screenshots.
3. A second project showing a different engineering skill (for example, games or productivity).
4. A small focused technical project demonstrating testing, architecture or API integration.

## Case study structure
Use `PROJECT_README_TEMPLATE.md` as the starting point for each project. Keep claims factual and distinguish shipped functionality from planned features.
